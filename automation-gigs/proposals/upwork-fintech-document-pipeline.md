How I handle low-confidence extractions (your specific question):
- Every field carries its own confidence, not just the document as a whole.
- A document is accepted only when classification confidence is >= 0.85, every
  extracted field is >= 0.80, and it passes all business rules. Anything else lands in
  a `needs_review` queue with the exact reasons attached (which field, what threshold,
  which rule), so a reviewer fixes one thing instead of re-reading the whole document.
- Fail-closed by design: any exception anywhere in the pipeline routes the document to
  review with a summary. Silent drops are the one failure mode I engineer against
  hardest, because in finance a missing document is worse than a slow one.
- Thresholds live in one config block and are documented, so you can tune the
  accept/review split against your reviewers' capacity.
